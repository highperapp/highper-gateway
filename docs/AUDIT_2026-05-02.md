# Highper Gateway — Pre-Release Audit (2026-05-02)

**Scope.** Validate the 15 stated use cases for public release readiness, and prepare for a 16th: AI/LLM Gateway (LiteLLM/Portkey/Helicone-class). The audit covers the entire `highper-gateway/src/` tree, all docs in `docs/`, and informal running notes (`reverse-proxy-quick-progress-notes.txt`).

**Companion documents.**
- `docs/USECASE_16_AI_LLM_GATEWAY.md` — design for the new use case.
- `docs/PHASED_RELEASE_PLAN.md` — sequenced milestones derived from this audit.

**Method.** Strategic doc digest + six parallel source-tree audits (L4/L7/Hybrid; TLS/RateLimit/WAF; HTTP3/WS/gRPC; DB/PHP-FPM/GraphQL; Cache/Discovery/Geo + cross-cutting; AI/LLM landscape). Citations use `path/file.rs:LINE` from the working tree.

**Verdict at a glance.** Code quality is high (panic elimination complete, 763/763 unit tests passing per `VALIDATION_REPORT_2026-01-11.md`). The release-blocking issues are mostly **integration completeness** and **operational validation**, not algorithmic. UC16 is greenfield.

---

## 1. Executive summary

### 1.1 What is solid

- **HTTP/1.1 + HTTP/2 proxy core:** 8 LB algorithms (`src/proxy/loadbalancer.rs`), connection pooling, retries with exponential backoff, circuit breakers, EWMA-ish response-time selection (rolling window), middleware chain. Production-grade.
- **TLS termination:** rustls-based, ALPN, SNI routing with hot-reload, ACME HTTP-01, mTLS client-cert validation with subject/issuer/serial/fingerprint policies, OCSP/CRL fetcher framework, CA bundle management. Functionally rich.
- **HTTP/3 / QUIC:** quiche-based, BBR, 0-RTT, address-validation tokens via HMAC, `Alt-Svc` advertising. Workable termination.
- **WebSocket:** RFC 6455 upgrade, key derivation, sticky sessions via cookies, ping/pong keepalive, circuit breaker, recovery, graceful shutdown coordinator.
- **gRPC:** detector, status-code mapping, streaming frame parser, gRPC-timeout parsing per RFC, `grpc.health.v1` framework.
- **PHP-FPM:** full FastCGI record protocol (BEGIN_REQUEST/PARAMS/STDIN/STDOUT/STDERR/END_REQUEST), Unix + TCP sockets, basic pool with idle reuse — by far the most complete subsystem.
- **Cache:** four real backends (InMemory/Disk-with-zstd-and-LRU/Redis/MultiTier), `cache_or_set`, mget/mset.
- **Discovery:** Consul + etcd polling clients, Static backend with TCP health probes, registry abstraction.
- **Geo:** MaxMind + IP2Location adapters, haversine nearest-server selection.
- **DSL:** pest grammar, Caddy-like syntax, hot-reload via file watcher.
- **WASM plugins:** wasmtime engine with fuel limits and epoch interruption.

### UC1 — Layer 4 TCP (Pure TCP Proxying)

**Inventory.**
- `tokio::io::copy_bidirectional` zero-copy forwarding (`src/tcp/proxy.rs:287`).
- 5 LB algorithms in `BackendSelector` (RoundRobin, LeastConn enum'd, ConsistentHash, IpHash, WeightedRR) — `src/tcp/proxy.rs:103-150`.
- Connection pool with LIFO queue, idle TTL, validation (`src/tcp/pool.rs`).
- Protocol-aware health checks (TCP, MySQL, Postgres, Redis) (`src/tcp/health.rs`, `src/tcp/mod.rs:183-198`).
- Circuit breaker 3-state (`src/tcp/circuit_breaker.rs`).
- TCP_NODELAY, SO_KEEPALIVE/TCP_KEEPALIVE (`src/tcp/proxy.rs:264-275`).
- SO_REUSEPORT, large backlog (4096/8192), SO_LINGER, TCP_FASTOPEN (Linux) (`src/utils/socket.rs:24-199`, `src/tcp/server.rs:67-113`).
- Graceful-shutdown broadcast (`src/tcp/server.rs:115-166`).

**Gaps.**
- LB fallback path silently picks first backend on unimplemented algorithm (`src/tcp/proxy.rs:148`) — should error.
- No EWMA, no outlier detection, no retry budget.
- No request mirroring / shadowing / canary traffic split.
- No connection draining on reload.
- No Unix socket / abstract socket upstreams.
- No `splice(2)` — `copy_bidirectional` uses buffered I/O.
- No `TCP_USER_TIMEOUT`; no NUMA pinning despite `src/runtime/cpu_affinity.rs` existing.
- Latency P50/P95/P99 hardcoded to zero (`src/tcp/proxy.rs:72-76`).
- **Critical:** TCP server is **not orchestrated by `Runtime`** — see B1.

**Improvements.**
1. Wire `TcpProxyServer::start()` into `Runtime::run` with config-driven listener-per-protocol; share `ProxyState` and metrics. **Effort: 2–3 days.**
2. Implement EWMA peer scoring + outlier ejection (failure rate or latency Z-score). **Effort: 4 days.**
3. Add Unix-socket and abstract-socket upstream support to `BackendSelector`. **Effort: 1 day.**
4. Implement connection draining (stop accept, allow active for `drain_timeout`, then close). **Effort: 2 days.**
5. Replace `copy_bidirectional` with `splice(2)` on Linux for L4 paths. **Effort: 3 days.**
6. Wire real latency percentiles (HDR histogram). **Effort: 1 day.**

**Verdict.** Code is solid. **UC1 cannot ship in UC10 mode until B1 is fixed.** As a standalone TCP proxy invoked from a custom binary, UC1 is GA-ready.

### UC2 — Layer 7 HTTP (HTTP/1.1 Load Balancing)

**Inventory.**
- hyper 1.5 with http1+http2 (`src/proxy/server.rs:13-14`).
- 8 LB algorithms (RoundRobin, LeastConn, Random, IpHash, ConsistentHash, LeastResponseTime, PowerOfTwo, Maglev, Geographic) (`src/proxy/loadbalancer.rs`).
- Rolling-window response-time selection (last 100 samples, cached avg) (`src/proxy/loadbalancer.rs:115-150`).
- Circuit breakers + retry/backoff (`src/proxy/handler.rs:63-67`, `src/proxy/retry.rs`).
- Compression middleware (gzip/brotli/zstd/deflate) (`src/middleware/compression/`).
- SIMD-accelerated path matching (`src/gateway/routing/matcher.rs:11-90`).
- Hot-reload routing (`src/gateway/routing/hot_reload.rs`).
- Body-size limits, streaming bodies (`src/http/body_utils.rs`, `src/http/streaming_body.rs`, `src/http/proxy_streaming.rs`).
- `Alt-Svc` advertising (`src/http/alt_svc.rs`).

**Gaps.**
- No slowloris defense (no per-request read timeout on incomplete headers/body).
- No header size limits (single oversized header block crashes the budget).
- No HTTP/2 graceful `GOAWAY` — abrupt close.
- No PROXY-protocol v1/v2 emission to upstream.
- No request mirroring / canary traffic split (config exists, no impl).
- Static upstream weights (no live weight changes).
- No Unix-socket upstreams in HTTP client.
- "EWMA" is actually rolling-mean, not exponential.
- Admin-API WAF config converters stubbed (`src/proxy/handler.rs:175-177`).

**Improvements.**
1. Add per-request read/idle timeouts (slowloris defense). **2 days.**
2. Header-block size cap and 431 response. **1 day.**
3. Implement HTTP/2 `GOAWAY` graceful drain on shutdown. **2 days.**
4. PROXY-protocol v2 to upstream. **2 days.**
5. Request mirroring (% sample to shadow upstream, response discarded). **3 days.**
6. Replace rolling-mean with proper EWMA + retry budget (token bucket on retries per upstream). **3 days.**
7. Unix-socket upstream support in hyper client. **1 day.**

**Verdict.** Production-shippable for the no-extreme-edge cases. Slowloris and header-size gaps are unacceptable for an internet-exposed gateway and must be fixed in Phase 0.

### UC3 — HTTPS / TLS Termination (ACME, mTLS, OCSP)

**Inventory.**
- rustls TLS1.2/1.3 with ALPN (HTTP/2, HTTP/1.1) (`src/tls/manager.rs:244-248`).
- Dynamic `CertResolver` for SNI-based cert selection (`manager.rs:179-318`).
- TLS passthrough mode parses ClientHello SNI for L4 SNI routing (`src/tls/passthrough.rs:20-186`).
- Hot-reload of certs with validation (`src/tls/cert_reloader.rs`, `src/tls/cert_validator.rs`).
- ACME HTTP-01 challenge + store with TTL cleanup (`src/tls/acme.rs:95-124`, `src/tls/challenge.rs:19-113`).
- OCSP fetcher with retry/backoff and stale fallback (`src/tls/ocsp_fetcher.rs:86-277`).
- OCSP cache with auto-refresh task (`src/tls/ocsp_cache.rs:45-165`).
- CRL fetcher with delta-CRL framework (`src/tls/crl_checker.rs`).
- CA bundle loader (`src/tls/ca_manager.rs`).
- kTLS framework module (`src/tls/ktls/`).

**Gaps (P0).**
- **OCSP request body never built** (`src/tls/ocsp_fetcher.rs:346-383` returns empty Vec; comment "production should use proper OCSP library").
- **OCSP response only length-validated** (`ocsp_fetcher.rs:385-415`); signature/time/nonce/status not checked.
- **OCSP stapling never attached to `CertifiedKey`** (`src/tls/ocsp_stapler.rs:97-136`).
- **`needs_renewal()` returns `false` always** (`src/tls/acme.rs:199-204`) — ACME daemon will not renew.
- **CRL `extract_crl_number` / `extract_delta_crl_url` stubbed** (`src/tls/crl_checker.rs:543-555`).
- Synchronous file I/O in cert load path (`manager.rs:49-53`, `storage.rs:103-104`).
- ACME private-key PEM passes through `serialize_pem()` and may end up in DEBUG logs (`acme.rs:184`).

**Gaps (P1).**
- ACME DNS-01 / TLS-ALPN-01 missing (HTTP-01 only).
- No EAB (External Account Binding) for private CAs / Let's Encrypt commercial.
- No staging/prod URL switch in config schema.
- No session-ticket-key rotation strategy exposed.
- kTLS sendfile integration framework only — no syscall path.
- No post-quantum hybrids (X25519+MLKEM).
- No 0-RTT (rustls support gating).
- No ECH, no CT-log monitoring, no HPKP.

**Improvements.**
1. Use `rustls-cert-gen`-equivalent or pull in `ocsp` crate; write proper ASN.1 OCSP request + verify response (signature, thisUpdate/nextUpdate, status, nonce). **5 days.**
2. Subscribe `OcspStapler` to rustls' `CertifiedKey.ocsp` field on every refresh tick. **2 days.**
3. Implement `needs_renewal()` checking notBefore/notAfter window vs now() (renew at 30 days remaining default). **2 days.**
4. Add ACME DNS-01 with at minimum Cloudflare and Route53 providers. **5 days.**
5. Replace blocking `fs::read` in cert path with `tokio::fs::read`. **0.5 day.**
6. Wire CRL number + freshestCRL OID extraction (use `x509-parser` extension API). **2 days.**
7. Add TLS staging-URL config field and example config. **0.5 day.**
8. Decide on PQ posture; if pursuing, pin `rustls` feature flag and add hybrid kex. **3 days.**

**Verdict.** Solid framework; **not ship-ready until OCSP request/verify is real and ACME renews itself.** Without these, the project advertises "OCSP" and "ACME" in a misleading way.

### UC4 — API Gateway with Rate Limiting

**Inventory.**
- Two parallel implementations: `src/middleware/rate_limit.rs` (single-bucket per IP) and `src/gateway/ratelimit/{token_bucket,sliding_window,distributed}.rs` (per-key, multi-algorithm, Redis Lua).
- Sliding window with VecDeque-based timestamp tracking (`sliding_window.rs:82-170`).
- Distributed limiter with Redis Lua atomic token bucket (`distributed.rs:150-204`).
- API-key, JWT, OAuth2 authentication (`src/gateway/auth/{api_key,jwt,oauth2,oauth2_providers}.rs`).
- Request transform middleware (`src/middleware/transform.rs`).
- Empty `src/gateway/rate_limit/` directory exists alongside `gateway/ratelimit/` — confusing duplication.

**Gaps (P0).**
- **Distributed limiter fails open on Redis error without alert** (`distributed.rs:54-62, 140-147`). This is a security bypass under Redis incident.
- **X-Forwarded-For trusted unconditionally** (`middleware/rate_limit.rs:162-182`) — no proxy-trust list.
- Middleware version always-on with hardcoded 100/60s; cannot be disabled per route.
- No per-route limits (config has the field; runtime ignores it).
- TPM/TPD shape (token-denominated, see UC16) absent.

**Gaps (P1).**
- No GCRA / leaky-bucket smoothing.
- DashMap of buckets unbounded (no LRU eviction).
- `Retry-After` precision-loss (f64 → u64 cast).
- No Prometheus metrics for limit hits / fallthrough.
- Empty parallel `gateway/rate_limit/` should be removed.

**Improvements.**
1. Add proxy-trust-list config (CIDR allowlist) for X-Forwarded-For. Outside trust list, use socket addr only. **1.5 days.**
2. Add Redis-failure mode flag: `fail-open | fail-closed | local-fallback` with default = `local-fallback` (in-process limiter spills over). **2 days.**
3. Wire per-route limits from config to runtime (DSL + YAML). **1 day.**
4. Add GCRA implementation alongside token-bucket. **2 days.**
5. Add LRU eviction on bucket map (max-N). **0.5 day.**
6. Delete empty `src/gateway/rate_limit/`. **0.1 day.**
7. Add Prometheus counters `rate_limit_hits_total{route,key,algo}` and `rate_limit_redis_errors_total`. **0.5 day.**

**Verdict.** Algorithmically reasonable; **fail-open and X-FF blind trust are exploitable**. Phase 0.

### UC5 — HTTP/3 QUIC (quiche)

**Inventory.**
- UDP listener + quiche connection setup, Initial+Retry handshake (`src/http/http3_quiche.rs:177-180, 308-398`).
- HMAC-SHA256 address-validation tokens (`http3_quiche.rs:1060-1150`).
- BBR congestion control, 0-RTT, 10MB flow window, h3/h3-29/h3-28 (`http3_quiche.rs:1025-1050`).
- Streaming request body via mpsc channels (`http3_quiche.rs:631, 722`).
- 4-worker proxy task pool (`http3_quiche.rs:199-270`).
- LB + circuit-breaker integration (`http3_quiche.rs:695-712`).
- `Alt-Svc` header advertising with `ma=` (`src/http/alt_svc.rs`).
- QUIC metrics scaffold (`src/observability/quic_metrics.rs`) and JSON lifecycle logger (`src/observability/quic_logger.rs`).

**Gaps (P0).**
- **Connection migration disabled** (`http3_quiche.rs:1053`). Mobile clients undergoing NAT rebind will drop.
- **Unwrap in receive loop** (`http3_quiche.rs:403`) — malformed connection ID can panic the worker.
- **Backend response fully buffered** (`http3_quiche.rs:944` calls `body.collect().await`) — defeats the entire point of HTTP/3 streaming for large payloads.

**Gaps (P1).**
- No GREASE in transport params (interop hardening expected from H3 stacks).
- No packet pacing / GSO / sendmmsg — naive `send_to` + `yield_now()`.
- No ECN/DSCP marking.
- No HTTP/3 datagrams (RFC 9221) → no WebTransport / MASQUE.
- `Alt-Svc` not auto-injected on every HTTP response (only when explicitly called).
- Metrics are described but never `counter!()`-recorded (zero-data metrics).

**Improvements.**
1. Replace `unwrap()` at `http3_quiche.rs:403` with `if let Some(...)` and packet drop + counter. **0.5 day.**
2. Re-enable `set_disable_active_migration(false)` and validate path (CID rotation, anti-amp). **3 days.**
3. Stream backend response (chunked write to QUIC stream) instead of `collect`. **3 days.**
4. Wire metric emit calls (`counter!`, `histogram!`) at receive/send/handshake/0-RTT paths. **2 days.**
5. Auto-inject `Alt-Svc` on all HTTP responses when h3 listener is configured. **0.5 day.**
6. Add GSO sendmmsg path (Linux). **5 days.**

**Verdict.** Functional terminator, not yet an HTTP/3-native proxy. Backend buffering is the headline regression.

### UC6 — WebSocket Load Balancer

**Inventory.**
- RFC 6455 upgrade + accept-key derivation (`src/websocket/handler.rs:13-50, 191-197`).
- Sticky sessions via `HPGW_WS_SESSION` cookie (HttpOnly, SameSite=Lax) (`handler.rs:53-83, 121-128`).
- `tokio::io::copy_bidirectional` for client↔backend (`handler.rs:134-159`).
- Connection state machine (Connecting/Connected/Closing/Closed) and per-conn metrics (`src/websocket/connection.rs`).
- Configurable ping/pong with missed-pong threshold (`src/websocket/keepalive.rs`).
- Recovery / circuit breaker with 7 error classes (`src/websocket/recovery.rs`).
- Graceful shutdown coordinator with phased timeouts (`src/websocket/shutdown.rs`).
- 16MB message limit, 10-min idle, 1-hr session (`src/websocket/mod.rs`).

**Gaps (P0).**
- **`RwLock::read/write().unwrap()` in production paths** (`src/websocket/recovery.rs:148, 155, 161, 173, 176, 189, 195, 213`) — poisoning panic risk.

**Gaps (P1).**
- No `permessage-deflate` (RFC 7692) negotiation.
- No WS-over-HTTP/2 (RFC 8441) — no `:protocol = websocket` Extended CONNECT.
- No WS-over-HTTP/3 (RFC 9220).
- `copy_bidirectional` is byte-level, not frame-aware — cannot parse close codes for distinguishing 1000 vs 1006, no per-message metrics.
- No `Sec-WebSocket-Extensions` negotiation; only `Sec-WebSocket-Protocol` forwarded.
- No max-connection-count quota per backend.
- No incomplete-handshake timeout (slowloris-WS).
- No connection hand-off across reload.

**Improvements.**
1. Replace `RwLock` `unwrap` calls with `safe_lock!` macro that recovers from poisoning (already used elsewhere per `TODO.md`). **1 day.**
2. Add `permessage-deflate` negotiation + per-frame deflate (use `flate2` or `zstd`-equivalent if RFC permits). **5 days.**
3. Add Extended-CONNECT (RFC 8441) for h2 and (RFC 9220) for h3. **5–7 days.**
4. Replace `copy_bidirectional` with frame parser for: per-frame metrics, close-code preservation, max-message enforcement at frame boundary. **5 days.**
5. Per-backend connection quota + handshake-timeout. **2 days.**

**Verdict.** Strong feature set; the production-RwLock panic risk is the only real blocker. The other gaps are competitive-parity items.

### UC7 — gRPC Gateway

**Inventory.**
- HTTP/2 + content-type detection, gRPC path validation (`src/grpc/detector.rs`).
- gRPC-timeout RFC parsing (H/M/S/m/u/n) (`detector.rs:110-137`).
- 16-status-code → HTTP mapping (`src/grpc/mod.rs:169-191`).
- Frame parser (5-byte header + payload), encode/decode (`src/grpc/streaming.rs`).
- `grpc.health.v1.Health` Check method with proto-level encoding (`src/grpc/health.rs`).
- Streaming-body forwarding (zero-copy) (`src/grpc/handler.rs:94`).
- LB policies enum'd: RoundRobin/LeastRequest/Random/PowerOfTwo/ConsistentHash (`src/grpc/mod.rs:114-125`).
- Per-method metrics scaffold (`src/observability/grpc_metrics.rs`).

**Gaps (P0).**
- **Fresh `hyper` client per request** (`src/grpc/handler.rs:54-100`) — no connection pooling. Will collapse under realistic load.
- **Call type heuristic-only** — defaults to Unary regardless of streaming nature (`detector.rs:57-78`). Streaming RPC behavior depends on this.
- Trailers passed as headers, not real HTTP/2 trailers — gRPC clients may misinterpret.

**Gaps (P1).**
- No retry budget per method, no hedged calls.
- No gRPC-Web translation.
- No JSON transcoding (no proto-descriptor parsing).
- No gRPC-LB v2 / xDS.
- No compression negotiation (frame compression-flag set but never honoured).
- No server reflection.
- No `grpc-status-details-bin`.

**Improvements.**
1. Reuse a single `hyper` HTTP/2 client per upstream with pool (use existing `connection_pool.rs`). **2 days.**
2. Mark trailers properly via `http_body::Frame::trailers`. **1 day.**
3. Determine call type via configurable per-method registry (proto descriptor optional in MVP). **3 days.**
4. Add gRPC-Web binary + text framing translation. **5 days.**
5. Add retry budget per method (token-bucket on retries) + circuit-break per `:authority`. **3 days.**
6. Wire `grpc-encoding` (gzip/identity) — minimum honour identity, gzip nice-to-have. **3 days.**
7. Server reflection v1 passthrough endpoint. **3 days.**

**Verdict.** Detectors and framing are right. **Connection-per-request and call-type heuristic are blockers** for any real gRPC workload.

### UC8 — Database Load Balancer (MySQL, PostgreSQL, Redis)

**Inventory.**
- L4 protocol detection: MySQL `0x0a`, PostgreSQL StartupMessage, Redis RESP (`src/tcp/protocol.rs:14-109`); port fallback (3306/5432/6379) (`protocol.rs:100-108`).
- Per-backend pool with idle queue, semaphore limits, atomic stats (`src/proxy/database_pool.rs:259-505`).
- Pool prewarm + cleanup tasks (`database_pool.rs:445-479, 414-442`).
- TCP keepalive (`database_pool.rs:360-366`).
- Protocol-aware validation: MySQL COM_PING (`database_pool.rs:157-170`), Redis PING/RESP (`database_pool.rs:186-198`).
- Pool stats with reuse ratio (`database_pool.rs:482-504`).

**Gaps (P0).**
- **PostgreSQL validation is `peek()` only** (`database_pool.rs:172-183`) — no protocol-state check; pool can return broken connections.
- No failover / retry on backend down.
- No SSL/STARTTLS upgrade negotiation.

**Gaps (P1).**
- No read/write split (proxy is L4 only — no SQL parsing).
- No transaction-aware pinning (PgBouncer-style session/transaction modes missing).
- No prepared-statement awareness.
- No COPY-protocol awareness.
- No Redis Cluster slot routing or Sentinel master discovery.
- No sharding / hash-slot routing.
- No query mirroring / audit log of statements.
- Connection auth credentials are pass-through — no central credential management.

**Improvements.**
1. Real PostgreSQL validation via parameter-status / Query("SELECT 1") probe with TIMEOUT. **2 days.**
2. Add backend failover with circuit-breaker tie-in. **2 days.**
3. STARTTLS/SSLRequest negotiation for Postgres. **3 days.**
4. Redis Cluster slot map + MOVED/ASK redirection handling. **5 days.**
5. PgBouncer-style transaction-pooling mode (lightweight session-state tracking). **7 days.**
6. Mirroring + statement audit log (optional). **3 days.**

**Verdict.** Solid L4 baseline; missing the L7 features that distinguish a "database load balancer" from a "TCP proxy on port 3306". For "L4 with health-aware routing", ship-ready; for full UC8 ambition (esp. read/write split, Redis Cluster), more work.

### UC9 — WAF + mTLS

**Inventory (WAF).**
- Engine abstraction with 4 backends: Custom, Coraza, ModSecurity, AWS (`src/middleware/waf/{engine,custom_engine,coraza_engine,modsecurity_engine,aws_engine}.rs`).

### UC10 — Hybrid Multi-Protocol

**Inventory.** Modular library that *could* host L4+L7+H3+Admin in one process: HTTP+HTTP/3+Admin+Metrics tasks are spawned by `Runtime::run` (`src/runtime/mod.rs`) sharing `Arc<RwLock<Config>>`, `ProxyState`, hot-reload trigger.

**Improvements.**

3. Hot-reload pipeline for TCP (currently HTTP-only). **3 days.**

**Verdict.** **The hybrid story is undelivered.** Until the runtime can spawn a TCP listener alongside the HTTP listener from one config, "multi-protocol in one process" is not real.

### UC11 — CDN Edge Caching

**Inventory.**
- InMemory backend (DashMap, LRU cleanup, hit/miss counters) (`src/cache/backends.rs:18-179`).
- Disk backend (LRU eviction, zstd compression, atomic temp+rename writes, sharded files) (`src/cache/disk.rs:117-615`).
- Redis backend (`ConnectionManager`, SETEX TTL) (`backends.rs:182-326`).
- MultiTier (L1 InMemory + L2 distributed; backfill on L2 hit) (`backends.rs:331-423`).
- Tiered (memory hot + disk warm with promotion) (`disk.rs:617-731`).
- Cache manager unifies via `get_or_set`, `mget`/`mset`, pattern delete (`src/cache/manager.rs:78-325`).
- Gateway cache wrapper with `CacheEntry` (body+status+headers+TTL) (`src/gateway/cache/mod.rs`).

**Gaps (P1).**
- No `Vary` header support — cache key ignores Accept / Accept-Encoding / Accept-Language. **Correctness bug.**
- No cache stampede prevention (singleflight).
- No stale-while-revalidate; no SIEW-friendly RFC 5861 directives.
- No conditional GET (304 Not Modified) revalidation.
- No `Cache-Control` parsing (s-maxage, max-age, no-store, private).
- No surrogate keys / tag-based invalidation (acknowledged TODO in `LIMITATION_FIX_PROGRESS.md`).
- No `X-Cache: HIT|MISS` / `X-Cache-Hits`, no `Surrogate-Control`.
- No negative caching policy.
- No max object size at response level (only file-size at disk level).
- DefaultHasher (non-cryptographic) used for cache key (`disk.rs:209`) — collision-attack vector.

**Improvements.**
1. Cache key incorporates `Vary` header set. **2 days.**
2. Singleflight: in-flight map keyed on cache key; followers await. **2 days.**
3. RFC 7234-correct `Cache-Control` parser → directives → behaviour. **5 days.**
4. Tag-based invalidation (PURGE by tag); Admin API endpoint. **3 days.**
5. Conditional revalidation (If-Modified-Since / If-None-Match passthrough; on origin 304 update entry timestamp). **3 days.**
6. Replace DefaultHasher with SipHash-1-3 or BLAKE3 for cache key. **0.5 day.**

**Verdict.** Storage layer is excellent; HTTP-cache semantics are at v0.5. Functional for static-asset cache; risky for any URL with `Vary`.
